# fdash (step A) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A generic task runner, fdash (`tools/fdash/`, config `fdash.json`), and the gauntlet (`scripts/gauntlet.ts`) rebuilt on it with the same gates and report, static gates in parallel, on any OS.

**Architecture:** fdash has three modules: `config.ts` (load and validate `fdash.json`, commands and groups), `run.ts` (spawn a command's steps, groups with their own `jobs`, interruption), `cli.ts` (argument parsing and printing). The gauntlet keeps the process: `scripts/gauntlet-fingerprint.ts` (tree fingerprint) and `scripts/gauntlet.ts` (options, record, closing lines), calling fdash's `run`.

**Tech Stack:** Node 24 (`node:child_process`, `node:crypto`, `node:test`), TypeScript type-checked by `web/tsconfig.test.json`, git.

**Spec:** `docs/superpowers/specs/2026-11-07-fdash-design.md`

## Global Constraints

- Zero dependency; files run as `node <file>.ts` without a flag; imports use the `.ts` extension; no TypeScript-only runtime syntax (`enum`, parameter properties, `namespace`).
- `tools/fdash/` imports only `node:*` modules and its own files, and names no Home Quarters path.
- Gates, in order, with the commands of `scripts/gauntlet.sh` at `117ad23`: gofmt, go-vet, staticcheck, go-test-race, tsc, tsc-tests, vite-build, protocol-docs, oxlint, plugin-types, web-unit, site-build, e2e.
- `FDASH_JOBS` / `--jobs`: positive integer, default `max(1, floor(os.availableParallelism() / 2))`; anything else is refused with exit code 2 before any task runs.
- Record `.gauntlet/last-gates.log`: header `gates for: commit <short>, tree <12 hex>, started <YYYY-MM-DDTHH:MM:SSZ>, scenarios: <space-joined or all>`; `PASS <gate>` / `FAIL <gate> (log: <path>)` in gate order; `SKIPPED e2e` when skipped; closing `GATES GREEN` / `GATES RED: <n> failed` / `STATIC GATES GREEN; browser verification SKIPPED`, preceded when needed by `FAIL working tree changed during gates; rerun on the final tree` or `interrupted`; then `finished <time>`.
- Fingerprint excludes `server/CHANGELOG.md`, `desktop/CHANGELOG.md`, `docs/superpowers`.
- No changelog entry (tooling only, AGENTS.md).

## Review Focus

- `FDASH_JOBS=0`, `-1`, `abc`, `1.5`: exit 2 with a message naming `FDASH_JOBS`, no task started. (Task 3 test.)
- A command missing from PATH: its task fails with `ENOENT` in its log, the other tasks still run. (Task 2 test.)
- A Windows `.cmd` command (`pnpm`) with an argument containing a space: reaches the program as one argument. (Task 2 test on win32 only, a temp `.cmd` that echoes `%1`.)
- Ctrl+C mid-run: no new task starts, the run reports interrupted, exit 130, no orphan process. (Task 2 test through an abort signal; Task 5 manual check.)
- Untracked file names with spaces or accents: fingerprinted. (Task 4 test.)

### Task 2: fdash run

**Files:**
- Create: `tools/fdash/run.ts`, `tools/fdash/test/run.test.ts`

**Interfaces:**
- Consumes: `Command`, `Group`, `Config`, `expand` from Task 1.
- Produces:
  - `type Result = { name: string; ok: boolean; log: string; ms: number }`
  - `runCommand(c: Command, o: { root: string; log: string; extraArgs?: string[] }): Promise<boolean>`
  - `run(o: { root: string; config: Config; names: string[]; skip?: string[]; jobs: number; extraArgs?: string[]; onResult?: (r: Result) => void; signal?: AbortSignal; logDir?: string }): Promise<{ results: Result[]; interrupted: boolean }>` — `results` in the order `expand` gives, only for commands that ran; `logDir` defaults to a fresh `fs.mkdtempSync(os.tmpdir() + "/fdash.")`, each log `<logDir>/<name>.log`
  - `spawnSpec(cmd: string, platform: string, pathEnv: string, pathExt: string): { shell: boolean }` — true only on `win32` when the first match of `cmd` on PATH (trying PATHEXT extensions) ends in `.cmd` or `.bat`; when shell is used, each argument is double-quoted (inner `"` doubled)

Running a group: its members (after `skip`) go through a pool of `group.jobs ?? o.jobs`; a member that is a group runs recursively and takes one slot of its parent while it runs; every member runs even when one fails; the group's result is whether all passed. The names given to `run` behave as an implicit group with `o.jobs`. A command already started in this run (reached through another group) is not started again: the second reference waits for the first and shares its result. `signal` aborted: nothing starts afterwards, `interrupted: true`; running children are left to finish. A step's `cwd` is `path.join(root, c.cwd)`; `extraArgs` are appended to the last step of commands with `args: true`.

  - `runCommand: pass, non-zero exit, missing command (ENOENT in the log), output under failOnOutput, second step not run after a failing first`
  - `run: a group runs at most its jobs at once, the global value when it has none` (each command writes start and end timestamps to a file; 4 commands of 300 ms: a group with `jobs: 2` never overlaps more than 2; with `jobs: 1` none overlap; without `jobs` and `o.jobs: 3`, at most 3 and at least 2 overlap)
  - `run: default { jobs: 1, tasks: [static, e2e] } starts e2e after every static command ended, and results come in expand order`
  - `run: a failing member does not stop its group; the group fails`
  - `run: a command in two groups runs once`
  - `run: extraArgs reach only the args command` (it prints `process.argv.slice(1)` to its log)
  - `run: an aborted signal starts nothing more and reports interrupted`
  - `spawnSpec: shell only for a .cmd/.bat on win32` (temp dir on PATH with `t.cmd` and `u.exe`; `win32` → `t` true, `u` false; `linux` → false)
  - win32 only (`{ skip: process.platform !== "win32" }`): a temp `echo1.cmd` (`@echo %~1`) run with argument `"a b"` logs `a b`
