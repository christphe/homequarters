# Plugins Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Operator-installed plugins (Lua on the server, JS in a sandboxed iframe in the browser) that can add a pet following its owner, with admin enable/disable and a sample plugin.

**Architecture:** `internal/plugin` scans plugin folders and runs each enabled plugin's Lua in its own goroutine (gopher-lua) behind a bounded inbox, per office. The world reports plugin-visible presence and delivers plugin frames without ever kicking. The web client runs each plugin's JS in a `sandbox="allow-scripts"` iframe connected by a `MessageChannel`; a `PluginLayer` in `WorldView` draws and animates the sprites it is told about.

**Tech Stack:** Go 1.26 stdlib + `github.com/yuin/gopher-lua`, SQLite (modernc), TypeScript + PixiJS 8 + React 19, puppeteer e2e.

**Spec:** `docs/superpowers/specs/2026-10-17-plugins-design.md`

## Global Constraints

- Everything in English; user-visible client strings through `web/src/i18n.ts` (plugin-provided labels are the documented exception).
- `HQ_PLUGINS_DIR` empty = feature off: no plugin routes answer except `/api/plugins` → `[]`, admin list → `[]`.
- Plugin name `^[a-z][a-z0-9-]{0,31}$`, equal to its folder name.
- Lua: base without `dofile`, `loadfile`, `load`, `loadstring`, `require`, `collectgarbage`; plus `string`, `table`, `math`. Inbox 256. `update` at 10 Hz. Callback budget 50 ms. >10 runtime errors in a minute → crashed.
- `hq.send`/`hq.broadcast`: encoded ≤ 4 KB; per recipient, all plugins together, 10 msg/s burst 20; violations raise a Lua error.
- World delivers a plugin frame only if `len(p.out) < cap(p.out)/2`, never to invisible players; otherwise drop + count. Never kick for plugin traffic.
- KV: key ≤ 128 B, value string ≤ 4 KB, ≤ 1000 keys per plugin.
- Routes: GET/POST, fixed path, `/plugins/<name>/api<path>`, session required (401), POST body ≤ 16 KB, per-member limiter 5/s burst 10, plugin wait 1 s → 503, not running → 404.
- Assets: `public/` only, ext `.png .js .json .css`, ≤ 1 MB, no `..`, no dot-files, no symlink escape; `Cache-Control: no-cache`, ETag, `Access-Control-Allow-Origin: *`; running plugins only.
- Wire: `{"t":"plg","pl":<name>,"d":<json>}` both ways (client→server `d` ≤ 1500 bytes, bucket 10/s burst 20), `{"t":"plgs"}` server→client.
- Iframe: `sandbox="allow-scripts"` only, `srcdoc`, handshake within 10 s, ≤ 512 commands per batch, ≤ 30 batches/s, ≤ 32 sprites (≤ 2048×2048), ≤ 256 entities per plugin; over limits → plugin stopped on that page.
- Button label plain text ≤ 40 chars.
- Never log chat text, plugin message content, tokens.
- Commits: none until the user says "commit" (user preference); steps below say "checkpoint" instead.

## Review Focus

1. A member who is invisible when a plugin starts, or switches while it runs: must never be announced (`on_join`/`hq.players()`/delivery). Test in Task 4 and Task 2.
2. A server restart with players reconnecting: `on_join` replayed after `load()`, creatures restored with stored variants. Test in Task 5 (Go) and Task 9 (e2e restart).
3. Disable while a route request or messages are in flight: no panic, routes 404, clients drop everything. Test in Task 5.
4. A plugin whose Lua errors in `load()` or has a syntax error: listed as crashed/broken with an error string, office unaffected. Test in Task 1/2.
5. The page with a plugin idle: still renders on demand (~4 fps). Test in Task 9 (`idle`-style check).

### Task 2: Lua runtime

**Files:**
- Create: `server/internal/plugin/host.go` (Host, presence, budget), `server/internal/plugin/instance.go` (goroutine, LState, callbacks), `server/internal/plugin/api.go` (`hq` table, json conversion), `server/internal/plugin/host_test.go`

**Interfaces:**
- Consumes: `Info` (Task 1).
- Produces:
  - `type Player struct { ID uint32; Name, Role string }`
  - `type Sink interface { Deliver(to uint32, frame []byte) bool }` — `to == 0` means every online player; frame is the full `{"t":"plg",...}` bytes.
  - `type KV interface { Load(plugin string) (map[string]string, error); Set(plugin, key, value string) error; Delete(plugin, key string) error }` — Set/Delete must not block (queue; error when full).
  - `func NewHost(cat []Info, sink Sink, kv KV, log *slog.Logger) *Host`
  - `func (h *Host) Start(name string) error` / `Stop(name string)` / `Close()`
  - `func (h *Host) Status() []Status` with `type Status struct { Info; State string /* disabled|running|crashed|broken */; Error string }`
  - `func (h *Host) Running(name string) bool`
  - `func (h *Host) Presence(p Player, online bool)` — non-blocking, safe from any goroutine.
  - `func (h *Host) Message(from Player, plugin string, data []byte)` — non-blocking; dropped if plugin not running or inbox full.
  - `func (h *Host) Route(ctx context.Context, plugin, method, path string, req RouteReq) (RouteResp, error)` with `type RouteReq struct { Player Player; Body []byte; Query url.Values }`, `type RouteResp struct { Status int; ContentType string; Body []byte }`; errors `ErrNotRunning`, `ErrNoRoute`, `ErrTimeout`.
  - `h.OnChange func()` — called (from any goroutine) when the running set changes by itself (crash).
  - `h.Dropped(plugin string) int64` counters for metrics (events dropped, frames not delivered).

  - `hq.route("GET","/mine",fn)` → `Route` returns the table as JSON with status; unknown path → `ErrNoRoute`; `fn` sleeping in a busy loop → `ErrTimeout` within 1 s... (plugin crashed by budget first is acceptable: assert error is non-nil within 1.1 s); `hq.route` outside `load` raises.
  - `Stop` calls `unload`; `Route` after Stop → `ErrNotRunning`.

Lua↔JSON: tables with keys 1..n become arrays, otherwise objects; depth ≤ 32. Budget: `map[uint32]*tokenBucket` on Host under a mutex (10/s, burst 20).
